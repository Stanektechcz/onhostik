## Objective

### Package risk-policy (owner decision 13)

Every change of a price or a plan in the admin configuration takes a step-up **and a second person**; HIGH means a step-up
only; withdrawals (discount/promo code deleted, code paused, product off sale) stay with one person and a step-up; an
unclassified catalogue operation is four-eyes (fail closed); switching an automation rule takes a step-up.

### Package catalog-versions (owner decisions 2, 4, 5, 6, 11, 18, 21)

Plans stop promising what the platform does not provide, as NEW plan versions (existing versions, services and subscriptions
untouched): a code-defined revision `2026-09-honest-promises` (`domains/Catalog/CatalogRevisions.php`) published by the
operator command `onhost:catalog:revise` (dry run by default, `--apply`) through `CatalogCommand plan.publish`. The e-shop
product count is fair use, `cron_concurrency` is named in words, a new managed database never claims PITR, the seeder can
no longer rewrite a sold version, and the public student/school page is withdrawn.

### Package limit-raise (owner decision 8)

A limit of ONE running service can be raised, and the raise is paid for: the parent product's own option price per unit and
per period of the service's subscription, renewed every period by a subscription of its own. Only a number the platform
enforces for the family can be raised; a raise at no charge is a four-eyes decision bound to the service, the number, the
units and the price it waives. The unbilled staff paths (raw `resize`, `service.create` with its own entitlements) are closed.
