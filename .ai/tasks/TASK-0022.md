## Objective

### Package risk-policy (owner decision 13)

Every change of a price or a plan in the admin configuration takes a step-up **and a second person**; HIGH means a step-up
only; withdrawals (discount/promo code deleted, code paused, product off sale) stay with one person and a step-up; an
unclassified catalogue operation is four-eyes (fail closed); switching an automation rule takes a step-up.

## Context

### Package risk-policy

Spec `scratchpad/specs/risk-policy.json` (point 13) + orchestrator decisions. Before: no catalogue operation was four-eyes;
plan publish/rollback were HIGH (step-up only) and every other price operation (promo codes, discounts, option prices,
regional pricing, archive download fee) ran with no step-up at all. `ADMIN_CONFIGURATION_ARCHITECTURE.md` said "HIGH changes
require a second person", the code and AGENTS.md said HIGH = step-up; the owner decided HIGH = step-up, price/plan = four
eyes. `automation.toggle` was NORMAL although switching on a default-off rule reaches every existing service.
