## Objective

`brain.ps1 task finish` removes the worktree of a task whose branch was merged with GitHub's "Rebase and merge",
instead of refusing for ever.

## Context

Verified 2026-09-24: PR #6 (TASK-0001) was rebase-merged, which gives every commit a new SHA. `finish` asked only
`git branch --merged development`, against the **local** `development` (which lags `origin/development` until someone
pulls), so it refused although `git cherry origin/development <branch>` showed every commit as `-` and the trees
were identical. TASK-0001 was finished by hand.

## Contracts affected

`brain.ps1 task finish`: now runs `git fetch --quiet origin <base>` (moves only `origin/<base>`) and accepts a branch
that is an ancestor of `<base>` **or** has no commit outside `origin/<base>` (else `<base>`) per `git cherry`.
Refusal message names the upstream and the pending `+` commits. No other action changed.

## Acceptance criteria

- [x] `finish` accepts an ancestor branch (unchanged) and a rebase-merged branch (every commit `-` in `git cherry`).
- [x] Judged against `origin/<base>` when the ref exists, else the local `<base>`; fetch failure only warns.
- [x] Any `+` line, unexpected output or `git cherry` failure keeps the branch unmerged.
- [x] Clean-worktree, main-checkout and junction-only `node_modules` checks unchanged.
- [x] `Orchestration.Tests.ps1` asserts the new logic, statically and against a throw-away repository.
