## Objective

Close the loophole in `PlanPromises` that let the price-list/presentation code count as "the platform applies this
number" (brain card H278: a plan must never promise a limit the backend does not enforce). Introduce a hand-verified
`MetricRegistry` of what actually measures or enforces each catalog number today, use it for the numeric-promise
guard, and turn every currently-broken promise into one documented, ratcheted `KNOWN_GAPS` entry instead of a false
pass. Behaviour is unchanged: no prices, seeders, adapters or services were touched, only the guard's honesty.

## Context

`domains/Catalog/PlanPromises::readInSource()` excluded only paths containing `/Catalog/` from its "is this key read
by real code" text scan. `app/Http/Support/CatalogPresentation.php` — the price-list wording — sits outside that
exclusion and names every entitlement key it displays, so it satisfied its own guard. Read-only analysis (this task)
confirmed the guard was passing keys nothing measures or enforces: `products` (e-shop), `connections` (managed DB),
`dedicated_outbound_ip`/`dedicated_db` (mail/managed), and more found in the course of the fix (see Findings).

## Findings

None from a reviewer yet (self-review only). Self-found, beyond the task brief's initial gap list, while building
`MetricRegistry` (documented in `KNOWN_GAPS`/`MetricRegistry::REGISTRY` with reasons and evidence):

- INFO `domains/Catalog/PlanPromises.php` — `cron_concurrency` (task brief listed it as a candidate gap) is actually
  enforced: `IspConfigWebProvider::ensureClient/updateClientLimits` sets `limit_cron` from the client-wide sum
  (`ClientAllowance::SUMMED`). The `ServiceFeatures.php` "cron" feature-gate mismatch (`cron_jobs` vs
  `cron_concurrency`) is a cosmetic display default, not a sold, unenforced key — `cron_jobs` is never sold. Not
  added to `KNOWN_GAPS`.
- INFO four additional real gaps found while verifying every numeric/boolean key sold on active plans (not in the
  task brief's initial list): `snapshots` (VPS/VDS — display-only limit, no count check on `snapshot.create`),
  `php_workers_dedicated` (bool, web-hosting/profi + eshop/shop-peak), `spam_filter` (mail antispam tier), `bot_management`
  (CDN add-on, whose product has no executor at all), and `pids` (every game plan's `limits` bag — Pterodactyl's
  resource limits have no PID field).
- INFO the presentation-exclusion fix also surfaced two **boolean** capability-flag gaps
  (`dedicated_outbound_ip`, `dedicated_db`) that the task brief scoped to "non-numeric capability flags stay on the
  current rule." Since they only ever appeared in `CatalogPresentation.php`, excluding it would otherwise break the
  existing (must-stay-green) `PlanPromisesTest` test unless mislabelled as `FAIR_USE` — which would misrepresent a
  real gap as an operational fact. They were added to `KNOWN_GAPS` instead, alongside the numeric gaps (the ratchet
  mechanism applies uniformly regardless of PHP type in this implementation). **Flagged for reviewer confirmation** —
  see `.ai/handoffs/TASK-0017.md` Concerns.
