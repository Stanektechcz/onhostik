## Objective

The owner can stop a panel for real: a provider instance in state `contained` (and `disabled`) is refused to every caller —
customer, staff and the system — before an adapter or a credential exists; operations of such an instance wait instead of
running or failing; the backup scheduler and the health probe leave it alone. The doctor turns the staging isolation text
into rows (contained instances, Redis/cache prefixes, Turnstile, approval deciders, ClamAV) and reports every queue lane.

## Security considerations

- The refusal is in the one place every adapter comes from; it reads the stored state per call (one indexed query) so a
  long-lived worker holding an old model cannot call a panel contained after it loaded it.
- The error a caller may see carries no instance key (vendor neutrality); staff see the key on the parked operation.
- Setting/lifting stays HIGH (fresh step-up) and audited with the reason; an instance edit cannot bypass it.
- deploy-gate: the new drained family matches one exact shape (`automation|queue worker alive (<lane name>)`); any other
  row name outside the lists is still judged (test: `alive-ish` → exit 12).

## Migration considerations

None (no schema change; `contained` fits `state` VARCHAR(16)). Existing `disabled` instances become refused to everybody on
deploy — see *Findings* HIGH-1 for what that changes.

## Rollback

Revert the branch commits. A `contained` row left in the database would then be treated like an unknown state (not usable
for placement, but callable again) — set it to `disabled`/`maintenance` before rolling back, or keep the scheduler and
provider lanes masked (Path A controls).
