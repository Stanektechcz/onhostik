A plan that sells dedicated PHP workers on an ISPConfig product (web-hosting/profi) can only be placed, pinned, scheduled,
sold and plan-changed onto ISPConfig (a PHP-FPM pool per site); every other web/managed plan says "Sdílené PHP workery".

already runs is moved.

**Verification whether shop-peak/managed can land on ISPConfig — result: NO (recorded, not restricted).** Same workflow
and features would work, but (1) `eshop/shop-peak` promises WAF `pro + CDN + DDoS`; WafLevels `pro` includes `rate`, and
ISPConfig applies no rate limit (`IspConfigWebProvider::siteFeatures` `rate_limit => false`, aaPanel `true`); (2)
`ClientAllowance::SUMMED` counts `sites`, eshop plans carry no `sites` key, so an organization with another ISPConfig
hosting would get `limit_web_domain` one short and ISPConfig refuses the shop's site **after payment**; (3) ISPConfig has
no file manager for the site (`file_manager => false`). So `PlacementRules` binds a dedicated plan only when its product's
own executor is ISPConfig (profi); eshop/shop-peak stays on aaPanel and is reported (`undelivered`) by `onhost:doctor`
and `onhost:capacity:basis`. Owner decision needed (see Handoff).
