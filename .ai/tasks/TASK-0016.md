## Objective

Every mail action and listing that targets ONE mailbox proves first that the mailbox belongs to one of the service's
own mail domains; a mailbox that is not the service's is refused before any panel write, and its settings are never
read out. Fetchmail delivers only into a mailbox of the service.

## Context

The owner's standing rule (2026-09-24): "Do již existujících webů na ISPconfig a AAPanel nesmíme nijak zasahovat."
The shared ISPConfig mail server holds historical customers' mailboxes, and ISPConfig answers one administrator
session that never asks whose `mailuser_id` it was handed. An investigation reported that mailbox-level tools act on
any id; this task proved it (failing-first) and closed it. Audit row 103.

## Out of scope

- Domain-scoped mail tools (`forward.*`, `catchall.set`, `spam.list.*`, `list.*`, `fetchmail.delete`): they resolve
  their ids against the service's domain listing in the adapter already.
- The destination of a forward / catch-all / alias: deliberately unrestricted (forwarding your own mail out is the
  point; `MailAddresses` docblock).
- Building the mailbox ref from the domain the mailbox was found in (today: the first/resolved mail domain's node and
  client) — pre-existing, no security effect once ownership is proven.

## Dependencies

## Contracts affected

- API: `GET /v1/services/{id}/resources/{mail_autoresponder|mail_filters|mail_spam}?remote_id=` answers 404
  `mailbox_not_found` for a mailbox that is not the service's (was 200 with the stranger's data).
- API: `fetchmail.create` answers 422 `mail_domain_not_yours` when `destination` is outside the service's domains.
- Saga: `autoresponder.set`, `spam.policy`, `filter.create`, `filter.delete`, `mailbox.backup`, `mailbox.restore`,
  `fetchmail.create` fail non-retryably with `not_ours` before any panel write.

## Security considerations

Cross-tenant write and read on a shared panel. The only proof of ownership is the service's own domain listing
(`MailDomains::ownRow` over `across`); a web hosting without a mail domain has no mailboxes, so nothing passes.
The listing answers "not found" for a stranger's mailbox — the same as a mailbox that does not exist.
