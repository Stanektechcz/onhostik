## Security considerations

Security self-check (money/payments, ecc:security-reviewer style):
- The guard only REFUSES earlier; it never takes a payment path that was refused before. It runs after the idempotent-intent lookup, so an intent that already exists is still returned (a retry of a started payment is not broken when credentials disappear).
- No vendor detail reaches the customer: the message names the bank transfer, not the gateway; the old path made an outbound request with empty Basic credentials — that request no longer leaves.
- Guest checkout: refused before the account and the session are created (the old path left a signed-in account without an order).
- The public data exposes only a boolean (`cardPayments`) — no credential, no merchant id, no state of the secret store.
- Footer links are server-built from fixed slugs and one fixed external URL (`https://adr.coi.cz/cs`); no user input reaches them; Blade/seam output is the template's own `href` binding.
