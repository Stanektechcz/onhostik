## Objective

The public Comgate notification route accepts a notification only from an allow-listed address; an empty allow-list refuses
every notification (fail closed) instead of accepting all of them.

## Context

Phase W, package W1. `ComgatePaymentProvider::verifyWebhook` checked `$allow !== [] && ! in_array(ip, $allow, true)`: with the
default empty `COMGATE_CALLBACK_IPS` every address passed, and every forged notification made the platform call Comgate for a
status. Exact string match only (no CIDR), entries not trimmed.

## Security considerations

`$request->ip()` is the proxy's address unless `TRUSTED_PROXIES` names the reverse proxy; listing a proxy address would
re-open the route to anyone behind it (runbook says never do that). The status re-read stays the trust mechanism; the
allow-list only stops forged notifications from reaching Comgate.

## Rollback

Revert the commit. Operational alternative: none needed — fill `COMGATE_CALLBACK_IPS` with Comgate's addresses before go-live.
