## Objective

Nobody can accidentally get a real secret into the git history: `.env.*` files are ignored except the
`.env.example` template, the pre-commit hook that blocks a staged `.env` is wired up automatically for every
developer clone, and gitleaks scans every branch push, not only pushes to `main`/`development` or pull requests.

## Context

Audit `.ai/audits/2026-09-25-onboarding-audit/response-verified-2026-09-25.md`, row C11 (§2, line 43; follow-up
task row §6, line 284, "was TASK-0040"): the pre-commit hook is inert until `core.hooksPath` is set (nothing
enforced it in composer scripts), `.env.local`/`.env.staging`/`.env.testing` were not gitignored, and the
`secrets` CI job only ran on `main`/`development` pushes and PRs.

## Acceptance criteria

- [x] `.gitignore` ignores `.env.*` except `!.env.example`, and every currently tracked file
      (`git ls-files '.env*'` → only `.env.example`) still resolves the same way (`git check-ignore` confirms

      release directory (`infra/aapanel/deploy.sh`/`install.sh` run `composer install` without `--no-scripts`,
      so this script does run there, but that tree's `.git` is not inside it, so `git rev-parse
      --is-inside-work-tree` fails and the script exits 0 without touching anything).
- [x] `.github/workflows/security.yml`'s `secrets` job (name unchanged) runs on every branch push (the
      workflow's `push:` trigger no longer restricts to `[main, development]`), in addition to pull requests,
      the weekly schedule, and `workflow_dispatch`.
- [x] No existing tracked file becomes unreachable or misclassified by the `.gitignore` change; the full test
      suite and Pint stay green.

## Security considerations

This *is* the security fix (audit C11): reduces the chance of a secret landing in tracked history or in a
short-lived branch that CI never scanned. No new attack surface — the hook-setup script only ever runs `git
rev-parse` and `git config core.hooksPath .githooks`, both read/local-config-only, and always exits 0.

## Migration considerations

None. Existing clones that never had `core.hooksPath` set will get it set the next time anyone in that clone
runs `composer install` (or `composer setup`) — no forced action needed, no compatibility break.

## Rollback

Revert this commit. `.gitignore`/`composer.json`/`.github/workflows/security.yml`/`.githooks/install.php` all
revert cleanly; nothing else depends on them.
