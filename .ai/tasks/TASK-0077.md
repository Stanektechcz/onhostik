## Objective

A customer webhook carries only the public face of an event, is sent from the queue (the outbox relay never waits for
a customer's server), is signed the one way the docs describe, every webhook write goes through the bus with a risk
level, and the customer hears when an endpoint is suspended.

## Context

Package D4 of the API programme. Before: `WebhookDispatcher::payload()` put the raw outbox payload (operation ids, node
and vendor names, fraud scores, staff names, provider error text, correlation id) on the wire; every event whose name
started with a customer prefix went out, including the staff side (`order.settlement_failed`, `ticket.assigned`,
`sla.burn_rate`, …: 7 of 12 such events were delivered in the failing-first run); the HTTP call ran inside the relay
listener; `docs/api/README.md` described a `t=…,v1=…` header that was never sent; create/delete were controller writes
with a hand-made audit; a paused endpoint told nobody.

## Findings

Security review of PR #70 (coordinator, approve with changes) — all addressed on the branch, tests first (`tests/Feature/Webhooks/WebhookLimitsTest.php`, snapshot cases in `WebhookDeliveryTest`; 7 red before):
- MEDIUM M1 — ping/redeliver as an on-demand request source — ping cooldown 30 s per endpoint (DB), 20 redelivery requests per endpoint and hour (RateLimiter), 60 attempts per endpoint and minute in `attempt()` (over → waits, no failure), redeliver no longer resets attempts, at most 10 attempts per delivery (409 `webhook_redeliver_limit`).
- MEDIUM M2 — staff/platform free text on the wire — reasons, notes, incident/ticket/maintenance titles and subjects, state labels, work-offer scope, `monitoring.down.error` dropped; the built payload passes `Redactor` before it is stored.
- MEDIUM M3 — redeliver while claimed / attempts from a stale copy — requeue only when `next_attempt_at` is null or due and attempts < 10; attempts incremented in the row.
- LOW L1 — IPv4-mapped IPv6 — refused by name in `EgressGuard::isPublic` before the allow-list (was already caught by PHP's reserved flag; now explicit + test).
- LOW L2/L3 — ports and legacy http — https on 443/8443 only, at creation (422 `webhook_port_not_allowed`) and at every attempt (legacy rows fail without a request).
- decision (coordinator) — the whole backoff is waited out: first attempt + one retry per BACKOFF_MINUTES step (6 attempts, last ≈ 876 min), dead only when the last retry fails; `WebhookDispatcher::retryScheduleMinutes()` returns the cumulative offsets [1, 6, 36, 156, 876] for D3.
- docs — receivers MUST deduplicate on `X-ONhost-Delivery`; limits and ports documented.
