## Security considerations

Self-review (cookies, identity, customer input): (1) less is stored: no cookie by default, so no consent question; (2) the codes in the sign-up body were already accepted (`ref` max 16, `partner_code` max 24, both upper-cased and looked up; unknown codes ignored, registration never fails on them) — sending the same `?ref=` value as both cannot attribute to a wrong party: a partner code only matches an active partner, an invite code only an organisation's own `referral_code`, and self-attribution is refused by both services; (3) the URL parameter is a visitor-controlled value exactly as before (no new trust); (4) switching off ignores an old cookie rather than deleting it (it expires within 30 days; deleting would need a Set-Cookie to every visitor). No MEDIUM+ finding.
