## Objective

A release on the aaPanel host can no longer go live when the target fails the readiness check: the installed deployer
drains the workers, takes the site down, takes and verifies a backup, switches to a pinned SHA, builds, and judges the
target's `onhost:doctor` by row name plus `/up` and `/v1/status` **before** anything starts again. Staging is prepared
for launch on this path (`docs/runbooks/staging-launch.md`) — prepared only, nothing executed.

### Deviations taken during implementation (each stricter or forced; reviewers please judge)

1. `artisan down --with-secret` instead of `--secret=<value from a 0600 file>`: the secret never exists in an argv (`ps`),
   the helper reads it from `storage/framework/down` (where Laravel keeps it anyway).
2. The bypass goes to curl as a `-K` config file, not a cookie jar or `-H @file` (needs curl 7.55+; `-K` works everywhere).
3. `EXPECTED_SHA` is required on every environment, not only production.
4. `install.sh` resolves REF itself instead of sourcing a shared helper: it is downloaded as one pinned file before any
   checkout exists.
5. The nginx staging block switches the basic-auth realm off by a server-level variable (loopback, `/up`, payment
   callback) instead of `satisfy any; allow …; deny all` + per-location `auth_basic off`: the latter answers 403 on `/up`
   (satisfy any with deny all) and loses the exemption on the internal redirect to `/index.php`. ASSUMED until S1.
6. rc 6 (public `/up` failed after `up`) does not put the site down again: the gate already passed through the bypass and
   the units run; the hint is printed and `last-good` is not updated.
7. The drain also stops units in `activating`/`reloading` (a worker in auto-restart would otherwise come back on old code).
8. The CI e2e runs unprivileged: `chown` is stubbed with `systemctl` and the FPM reload; root-only behaviour is NOT TESTED.
9. (round 2) `.env` must be the SAME FILE as `ENV_FILE` (`[ .env -ef ENV_FILE ]`), not literally "a symlink to it": the
   property that matters is that Laravel loads the file the deployer judged; a symlink elsewhere, a copy or a separate
   file all fail it, and the Windows test sandbox (no unprivileged symlinks) uses a hard link, which also satisfies it.
10. (round 2) A new exit code 7 (a drained unit did not come back) instead of folding it into 5: the operator reads a
   different cause (journal of a unit, not the doctor).

## Security considerations

Root script: target PHP (artisan, composer) runs as root under `env -i` in a tree www can write (vendor/ is ignored by
the clean-tree check) — an OPEN escalation path, owned by the follow-up (root-owned code tree, `setpriv`, composer
`--no-plugins`). A root-owned code tree alone would NOT close it: `bootstrap/cache` and `storage/framework/views` are
www-owned on purpose (D32.13), and root also deserializes data www can write (file/redis cache, sessions). Round 2
narrowed this: root's artisan/composer read Laravel's framework caches only from a root-only directory of the run
(`APP_PACKAGES_CACHE`, `APP_SERVICES_CACHE`, `APP_CONFIG_CACHE`, `APP_ROUTES_CACHE`, `APP_EVENTS_CACHE`) and the build
publishes them for PHP-FPM; compiled views are dropped right after `down` (a writer racing that stays open); the
ownership repair never follows a symlink. Closed here: git injection from `.git/config`/hooks/fsmonitor (root-owned
`.git`, `GIT_CONFIG_NOSYSTEM`, own global config, `core.hooksPath=/dev/null`, `core.fsmonitor=false`); the target judging itself (the deployer and its
lists are installed root-owned from a verified SHA, forward-only, and a target carrying a newer deployer is refused);
fail-open APP_ENV; override laundering (SHA-bound, staging only, logged, unset before any target code runs); bypass
secret in argv/logs (`--with-secret`, stdout discarded, 0600 curl config deleted, re-down without a secret on failure);
provenance in production (SSH-signed annotated tag against root-owned `allowed_signers`; round 2: the last signature
block must be SSH, `gpg.program`/`gpg.x509.program` are `false` with an empty `GNUPGHOME`, `refs/tags/<REF>` only, the
`tag` header must name REF); the production decision (round 2: from the root-owned `ENV_FILE`, `.env` must be that
file — www could repoint the symlink); the judge's own provenance (round 2: installer requires the signed tag in
production, `FIRST=1` only on a host without a deployer, preflight checks the deployer files are root's and not
group/other-writable).
