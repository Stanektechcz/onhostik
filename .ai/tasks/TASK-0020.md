## Objective

**Package `provider-calls-audit` (owner point 16).** The operator can answer, from the platform's own logs and without
touching any panel, whether the TASK-0005 hole (a customer naming any ISPConfig remote id — shell user, database user,
mailbox, alias — and the platform acting on it without an ownership check) was used before it was closed:
`php artisan onhost:audit:provider-calls` prints or files a masked report with a verdict and a severity for every such
action, the refusals made after the fix (probing), the writes no operation explains, and how far back the logs reach.

## Acceptance criteria

- [x] A shell key / database-user / mailbox action on another customer's record, accepted by the panel, is CRITICAL (exit 1); an attempt the panel refused or never got is HIGH; a write the panel never answered (5xx/timeout) is graded as possibly done.
- [x] An action on the service's own record is CLEAN and listed only with `--include-clean`; another service of the same organization is MEDIUM.
- [x] A record owned by nothing on the platform (historical) is FOREIGN_UNMANAGED; a record with no evidence is REVIEW with its sys_datalog key.
- [x] Evidence of any age is used; only operations and writes inside the window are judged.
- [x] Refusals after the fix are grouped per actor as probes (HIGH at 3 or consecutive ids); writes no operation explains are listed.
- [x] Coverage per instance with a warning when the log starts after the window start; unreadable (truncated) rows counted.
- [x] Read-only proven: row counts of 7 tables unchanged, no HTTP request, only one file under reports/.
- [x] Nothing secret printed: no logged request/answer, names and addresses masked, an SSH key only as a fingerprint, Redactor + SecretMask on every string.
- [x] Bad options exit 2 (days, format, instance, output path, since/until).
- [x] The audited actions are derived from the guard; a unit test keeps them and the sys_datalog map in parity.

## Security considerations

- Read-only by construction: reads through Eloquent/query builder only; no CommandBus, no ProviderRegistry, no Http; the only write is the report file on the private `local` disk (no URL is generated although the disk has `serve => true`).
- The report never contains a logged request or answer (legacy rows may hold unmasked secrets); whitelisted fields only; names/addresses masked; SSH key → `Redactor::fingerprint`; every string through Redactor + SecretMask. The operation's `desired` is read for the target fields only and never printed.
- `--output` is confined to `reports/` (no `.`/`..`/empty segment, restricted characters, the format's extension) and never overwrites an earlier report without `--force`.
- Customer-supplied text is stripped of control characters, DEL and bidi overrides before it is printed (no terminal escape via `--stdout`); Markdown cells escape `|`, `<`, `>`, backticks.

## Migration considerations

None (no schema change). On a large production copy the scans stream with `lazyById`; `provider_calls.action` is not indexed, so a run can take minutes — read-only, no index added.

## Rollback

Revert the commit(s); nothing to undo in data (the command writes none). Delete any report files under storage/app/private/reports.
