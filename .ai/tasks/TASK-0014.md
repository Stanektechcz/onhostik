## Objective

The platform never writes to, suspends, changes or deletes a site on ISPConfig or aaPanel that it did not create
itself. Historical sites (made by hand before ONhost) stay untouched; resources the platform created stay fully
manageable.

## Context

The owner's rule (2026-09-24): „Do již existujících webů na ISPconfig a AAPanel nesmíme nijak zasahovat při vývoji.
Toto jsou historické weby do kterých nový systém nesmí jakkoliv zasahovat. Na panelech mimo historické weby však může
provádět úpravy, vytvářet nové weby a ty editovat a spravovat."

Read in the code before opening the task: every `StepContext::bind()` caller writes `ownership: ['managed_by' =>
'onhost']` unconditionally — also when `provision()` answered `alreadyExisted: true`, i.e. the panel already had the
site — and nothing anywhere reads `ownership`. Brain card H304: adoption starts with a read-only inventory and an
explicit confirmation of ownership, never implicitly.
