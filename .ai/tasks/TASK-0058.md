## Objective

A customer who brings a domain to ONhost pays for the year of renewal the transfer buys at the registrar; a transfer nobody paid
for is refused, a failed or abandoned one gives the money back, and the transfer code is never kept beyond its use.

## Context

HIGH finding of TASK-0056 (`.ai/tasks/TASK-0056.md` Security): `POST /v1/domains/transfer-in` started the transfer saga with no
wallet hold; `SubmitTransferStep` renews the name from the platform's registrar credit; a cart line `action: transfer` was priced
by `QuoteService` (at the catalogue's transfer price — 0 Kč for .cz) but `DomainService::createFromOrderItem` called `register()`.
The panel's transfer chip stays off (`FLAGS.transferIn = false`, TASK-0056) until a screen sends `order_item_id`.

## Contracts affected

- `POST /v1/domains/transfer-in`: new optional body field `order_item_id` (the paid transfer line). Without it a customer gets
  `422 transfer_needs_order` (field `order_item_id`). With it: `404 not_found` (not the organization's transfer line),
  `422 transfer_order_mismatch` (line is for another name), `409 transfer_order_not_paid`, `409 transfer_already_submitted`,
  `409 transfer_line_closed`. `period` is taken from the paid line, not from the request. Staff acting as staff
  (`StaffActor::acts`, i.e. a future /v1/staff route) may still transfer without an order, on the platform's authority.
- Cart/quote: a domain line's `config.action` must be `register` or `transfer` (`422 domain_action_invalid`); keys a client might
  put a transfer code under (`auth_info`, `authinfo`, `authid`, `auth_code`, `auth_id`, `transfer_code`, `epp_code`) are dropped.
  A transfer line is priced at the list RENEWAL price × years (TLD discount for `transfer` still applies when staff set one).
- Order line `config`: `awaiting_transfer_code` (ISO time) while waiting; `transfer_code_received_at` / `transfer_code_expired_at`.
- Audit actions: `domain.transfer_awaiting_code`, `domain.transfer_code_expired`; `domain.transfer_in` gains `order_item_id`, `paid_by`.
- Config key read with a default (not added to config/onhost.php): `onhost.domains.transfer_code_wait_days` (30).

## Acceptance criteria

- [x] A customer's direct transfer-in without a paid order line is refused (422) and nothing reaches the registrar.
- [x] A paid cart line `action: transfer` is transferred (domain-transfer), never registered (no domain-create); the order's hold is
      captured for exactly the quoted line; the domain and line end active.
- [x] A transfer the registrar refuses fails the line; the settlement releases the hold (line `refunded`, revenue 0).
- [x] The code reaches the registrar once and appears in no log line, no table (outbox, audit, operations, order lines, quotes,
      idempotency store, …); the secret row is wiped after use.
- [x] The code is accepted only for the organization's own, paid, still-waiting line, once.
- [x] A paid line whose code never came fails after 30 days (nightly `onhost:commerce:prune` → `expireUnpaid`) and the money goes back.

## Security considerations

- The code is collected only after payment, through the existing step-up (HIGH) `transfer_in` command; it lands only in
  `domain_transfer_secrets` (encrypted cast, 7-day TTL, wiped by `consume()`); registrar operation records keep `[redacted]`.
- The claim of a line happens under `lockForUpdate`, so two hand-overs with different keys cannot start two transfers.
- Fixed in passing: `register()` / `transferIn()` reused an existing domain row with `tap($domain)->forceFill()->save()`, which
  returned save()'s bool and crashed on `->id` (a failed or deleted name could never be registered or transferred again).
