## Objective

One end-to-end Pest flow (real HTTP routes + scheduled commands, fixed clock) for the end of a web hosting and of an account: cancel at period end and undo, immediate cancel behind a destructive preview and a step-up, the undo inside the restore window, the removal of everything under the site on the panel while historical rows stay, the 14-day withdrawal, and the owner-only, step-up, 14-day account erasure. It found and fixes four product bugs.

## Context

Programme E10. Bugs found by the flow (each fixed minimally here): (1) revoking `cancel at period end` left auto-renew off, so the service ended anyway; (2) the final archive of an ISPConfig site with a database always failed (no database login passed to the dump), so such a site could never be cancelled; (3) the mail template `service-deletion-scheduled` did not exist, so the customer was never told and the outbox row failed for ever; (4) ISPConfig had no seam for its file half, so no e2e could archive a site (test seam `IspConfigWebProvider::$transportFactory`, no production behaviour).
