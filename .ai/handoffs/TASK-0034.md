## Outcome

- **Archive preflight (applies directly):** every unpack the aaPanel adapter does as root — `AaPanelTransport::extract`
  (panel UnZip: customer extract, import, restore, migration) and `restoreFromArchive` — is listed on the node first
  (`AaPanelArchivePreflight`, report-only output so 100k-file sites fit). Refused: hardlinks, devices/fifos, absolute
  names, `..`, anything beneath a symlink of the same archive, symlinks in a zip, symlinks whose target leaves the site.
  Symlinks that stay inside the site are kept (Laravel `public/storage`, release links) — see Decisions in the task file.
- **Temp files (applies directly):** shell output/exit files, download chunks, restore staging and preflight listings live
  in `/root/.onhost-shell` (0700) instead of world-readable `/tmp`.
- **Tenancy switch (behind `--apply`):** `php artisan operator:aapanel:tenancy` (= `onhost:aapanel:tenancy`) lists aaPanel
  nodes whose platform services belong to more than one organization, their services, the organizations to tell, what
  closes and what stays — and changes nothing. `--apply` closes them through the bus (`ProvisioningCommand instance.upsert`,
  HIGH, audited) as instance option `tenancy.closed`; idempotent. `--reopen --instance=<key>` reverts one node.
  On a closed node: no in-panel file manager (browse/read/edit/upload/mkdir/delete/rename/copy/chmod/archive/extract),
  no site import, no new shell cron or changed command, no cron run on demand — refused with a customer-readable reason.
  Stays: SFTP/FTP, backups/restores, databases, jobs already running (as the site user), pause/resume/delete of jobs,
  re-confining an old root job with its own command (`onhost:services:cron-confine`), the suspension cron switch.

## Release notes for existing customers

- Everyone on aaPanel: an archive whose contents would reach outside the site (links out of the site, hardlinks,
  absolute or `..` paths, links inside a zip) is no longer unpacked; the operation fails with the reason. Ordinary site
  archives, including in-site links, unpack as before.
- Customers on an aaPanel server shared with other customers — **only after the operator runs `--apply`, after the dry
  run and a notice (owner default O1)**: the control panel's file manager, site import, new/changed scheduled shell
  commands and "run now" are no longer available on that server. Files are uploaded over SFTP/FTP; scheduled jobs that
  already run keep running; jobs can still be paused and deleted. Suggested notice text: "Your web hosting runs on a server
  shared with other customers. For the safety of your site, files and scheduled shell commands can no longer be changed
  from the control panel; please use SFTP/FTP. Existing scheduled jobs keep running."
