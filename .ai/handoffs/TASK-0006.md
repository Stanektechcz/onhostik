Task / Status:    TASK-0006 / SELF_VERIFIED

**Outcome.** Taking a cancellation back now reaches the sites the service carried. They are no longer left with a
`terminate_at` of their own for the purge to collect thirty days later.

**Files.**

- `domains/Provisioning/Workflows/ServiceActionWorkflow.php` — `endIncludedServicesStep` marks each site it ended
  (`included.ended_by`, `ended_at`); `holdIncludedServicesStep(false)` undoes the scheduled deletion of exactly those
  first, then resumes them, lifting only its own `review` hold and only when that hold is the sole one.
- `domains/Services/ServiceService.php` — new public `undoScheduledDeletion()`, which exposes what the private
  `cancellationCleared()` already did, so a deletion can be taken back without a resume.
- `tests/Feature/Services/IncludedSitesTest.php` — two new cases.
- `docs/runbooks/production-readiness-audit.md` (row 93), `docs/context/CURRENT_STATE.md`.

**Contracts.** None changed. One new public method on `ServiceService`; no endpoint, event payload, schema or config
key moves. `service.deletion.cancelled` is published for a carried site as it already was for its parent.

**Verification.**

- VERIFIED — failing-first: "brings back the sites it carried when the customer undoes the cancellation" failed on the
  unfixed code with the site still holding `terminate_at` thirty days out.
- VERIFIED — after the fix: `tests/Feature/Services/IncludedSitesTest.php` 7/7; full suite in this worktree
  **906 tests / 14 814 assertions green**; Larastan 0 errors; Pint clean.
- VERIFIED — the chain was read end to end before writing anything: `endIncludedServicesStep` →
  `scheduleRemovalStep` (`terminate_at = now + graceDays`, state SUSPENDED) → `cancellationCleared` patching only the
  service it is called on → `holdIncludedServicesStep(false)`'s condition → `onhost:services:purge` selecting
  `terminate_at <= now()` with state SUSPENDED/FAILED.
- NOT TESTED — no live panel; the purge itself was not run against a node.

**Concerns.**

1. **Sites already lost this way cannot be recovered by this change.** If any customer undid a cancellation in the
   past and a carried site was purged, its archive is what remains (60-day retention, `archive.restore`). Worth a
   query before go-live: services with `tags.deletion_cancelled` whose carried children are TERMINATED.
2. A carried site that an abuse case holds now stays suspended **without** a pending deletion. That is deliberate, but
   it means such a site can sit suspended indefinitely until the case is closed — an operator has to see it. There is
   no report for that yet.
3. Ten further findings of the six-lens audit remain open and unverified; the next one to read is the ISPConfig client
   whose limits are written from a single service's entitlements (`.ai/handoffs/TASK-0005.md`, concern 2).
