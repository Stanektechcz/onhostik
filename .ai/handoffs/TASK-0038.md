## Outcome

`php artisan onhost:forensics:lookback [--since] [--until] [--source=*] [--json]` is a strictly read-only report
(permission program P0-01 / IF-0, D16). For each verified exploit of Phase 0 it lists the tables it checked with
their row counts. It lists the hits, each marked `confirmed`, `possible`, `attempt` or `use_or_attempt`. It lists the
unknowns: what the database cannot tell, and which tool can. It adds the notes and the fixed limits. Every report
carries `standing_state`, the baseline rule. Exit codes: 0 when there are no hits, 1 when there are hits, 2 for bad
options.

| Source key | Exploit | What it reads |
| --- | --- | --- |
| `owner_demotion` | TD-1 | invitations accepted and attach rows written for the owner **of that moment** (from the ownership transfers) at a lower role, plus the current owner's membership |
| `game_panel_identity` | PA-01 | `provision.game` operations (`ptero_user_created`), bindings, `game_servers`: a panel user created for org A under org B's service |
| `discord_after_removal` | G1 | `organization.member.attach`/`remove` audit vs `discord_links.last_used_at`, audit rows with `discord:` and `hook:` sessions, `support_ai_runs` `discord:` rows, enabled `action_hooks` of former members, re-admission gaps |
| `aapanel_outside_root` | PA-02 | `service.action` file, cron and `command.run` operations and the upload audit vs the site root in `provider_bindings.meta.path`; every aaPanel service is a standing unknown for TASK-0034 |
| `token_cross_org` | PA-04 | audit rows with `session_id = token:<id>` whose token belongs to another organization |
| `staff_own_org` | SS-1/SS-5, EXPL-1..3, IF-8 | staff hold lifts, forced purges, self-grants (the `mayGrant` bypass) and reinstatements in organizations the staff user belongs to |
| `partner_payouts` | P1/P2 | payout amount vs allocated commissions (rejected ones excepted); the IBAN of every bank-transfer payout, rejected ones included, vs earlier paid payouts; first payouts as unknowns |

It runs SELECTs only, inside a transaction that is always rolled back. It uses no CommandBus, adapter, HTTP, file,
route, schedule or event. Output goes to stdout only: no e-mail addresses, no full IBANs, and for PA-02 only the
offending paths.

The runbook `docs/runbooks/breach-register.md` covers the **mandatory baseline run** first. That is production
before the first Phase 0 deploy, or a restore of the last backup taken before it: no migrations, no repair
commands, hashed and attached first. It then covers running the command and keeping the output private, reading the
verdicts with a follow-up per source, and recording findings in the cyber incident. Last come the Art. 33/34 notices,
drafts only, never sent without the owner's recorded decision (§10 O3).
