**Outcome.** `Service::primaryBinding()` is deterministic: it answers with the binding of the service's own family.
The nightly PostgreSQL run of the whole suite was failing on the consequence — `ServiceIdentityCheck` refusing to
archive a web service because the platform had decided it *was* its mail domain.

**Files.**

- `domains/Services/Models/Service.php` — `primaryBinding()` takes the first binding whose `remote_type` belongs to
  the service's family, falling back to the first row; `created_at` and the id only break a tie inside the family.
  `bindings()` gained its generic return type.
- `domains/Services/ServiceIdentityCheck.php` — `TYPES` is public: "which types may this family bind" and "which of
  my bindings am I" are one question, and letting them drift apart is how a proof came to look at the wrong resource.
- `app/Http/Controllers/Api/V1/ServiceController.php` — the binding list in the service detail is built with
  `array_map` over `->all()`; unchanged JSON.
- `tests/Feature/Services/PrimaryBindingTest.php` (new), audit row 99, `CURRENT_STATE.md`.

**Contracts.** `ServiceIdentityCheck::TYPES` public. Nothing else.

**Verification.**

- VERIFIED — failing-first: with a `mail_domain` binding written one second before the site's own row,
  `primaryBinding()` returned `mail_domain` and the identity check's `binding_type` failed.
- VERIFIED — after the fix it returns the `web_domain` row and the check passes.
- VERIFIED — gates: Pint clean, Larastan 0 errors, Pest **918 tests / 14 872 assertions** green.
- VERIFIED — the failure was read in the CI logs of three runs first (`development` 15:31 and 16:25, then the
  TASK-0011 branch): two different tests, one cause.
- NOT TESTED locally on PostgreSQL — the local suite runs on SQLite, where the old ordering happened to be stable.
  CI runs the suite on PostgreSQL 16 and is the check for it.

**Concerns.**

1. `provider_bindings.created_at` has second precision, so ties are the normal case for rows written by one
   operation — anything else that orders by it alone has the same problem. Nothing else in the code base does today.
