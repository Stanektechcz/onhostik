**Outcome.**

- **P0-04 (IF-15).** A new listener `Onhost\Domain\Organizations\Listeners\RevokeMemberSideDoors` on
  `onhost.organization.member.removed` / `.role_changed` revokes the person's Discord links and switches off their action hooks.
  Removal takes all of them. A role change takes what the new role could not have made: a link needs `organization.manage`,
  a hook its action's permission. Each write has an audit record (`integration.discord.revoke`, `integration.hook.disable`).
  Every `/onhost` read (`services`, `status`, `ask`, button clicks) now resolves the person per request. A link held by
  someone who is no current member is revoked the moment it is used. What a member sees comes from `AssistantScope`, and
  `ask` requires `AssistantScope::mayChat`. The hook trigger also refuses and disables a hook whose creator is no current
  member. The one-off `operator:integrations:orphan-links` lists the old leftovers as a dry run and revokes them only with
  `--apply`.
- **P0-05 (IF-11).** `archive.restore` from both endpoints now goes through `ServiceArchiveService::restore`. The generic
  `/services/{id}/actions` is routed there by `ServicesCommandHandler`. Two checks run there. The actor needs `backup.read`
  where the archived service lived; without it the reply is 404. The actor also needs `backup.restore` at the target's
  project or organization; a resource `svc_restore` gets 403. The workflow copies the live target first (`pre_restore`).
  The safety copy now fails closed: a failed web copy was being promoted to `completed` on retry. The fee is waived only
  after `requestAction` accepted the restore.
- **P0-06 (IF-17).** The team page fails closed when `member_role` is missing. A role select in the form replaces
  `window.prompt`. Removing a member is an option of that select and asks for confirmation. All 14 customer presets are
  listed, and `partner` reads "partner (jen provize) / partner (commission only)". The projects page is still offered only
  project-capable roles (no guest or partner).

## Release notes for existing customers

- **Discord.** Someone who left your organization can no longer use a linked Discord account. The same applies to a
  lowered role that could not link one (anything below administrator); that link is revoked. `/onhost services` and `status`
  show only the services your own role shows in the panel. Re-link from the panel if you still need it.
- **Action hooks.** A hook created by someone who has since left, or whose role can no longer run that action, is switched
  off, not deleted. The list shows the reason (`member_removed` / `role_changed`). Create a new hook under a current member
  if you still need it.
- **Leftovers from before this release.** The operator reviews a dry run (`operator:integrations:orphan-links`) before
  anything is revoked (`--apply`). Nothing about existing links and hooks changes silently at deploy, except that a
  non-member's link stops at its next use.
- **Archive restore.** Only someone who may restore backups for the whole project or organization can restore the archive
  of a cancelled service, and only for a service whose data they may read. A single shared service with the "restore"
  capability no longer allows it. The live target is copied before the archive is written over it; if that copy cannot be
  made, nothing is overwritten.
- **Safety copies.** A restore, database import or reinstall whose safety copy failed now stops. Before, a failed copy could
  be marked finished on retry.
- **Team page.** Changing a role uses a list of every role. Removing a member asks for confirmation. The "partner" role is
  labelled "partner (commission only)".
