**Outcome.** `PlanPromises`'s guard no longer trusts the price list as proof a number is applied, and — this pass —
no longer trusts a registry row's `status` alone, ignoring which product family it was actually verified for. A new
`domains/Services/Metering/MetricRegistry.php` records, per entitlement/limit key, what actually measures or
enforces it today (status `measured` / `enforced_only` / `gap`, with sources, reasons and the product families each
row is verified for). `PlanPromises` checks every numeric (int, float, **or numeric string**) or, where a genuine
gap surfaced, boolean key against that registry — **scoped to the plan's own product family** — `FAIR_USE`, or the
`KNOWN_GAPS` ratchet constant (may only shrink); non-numeric capability flags otherwise keep the original text-scan
rule. `onhost:doctor` shows the known-gap list as a standing WARN and any *new*, untracked gap as FAIL. No prices,
seeder, services or adapters changed — only the guard's honesty.
