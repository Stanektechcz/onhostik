# Handoff — TASK-0021

## Package "identity" (owner decisions 14 and 15)

```
From / To:        onhost-backend → orchestrator
Task / Status:    TASK-0021 / IN_PROGRESS (package "identity" self-verified; the credit package follows)
```

**Outcome.** A password change in the portal now revokes every personal Sanctum token of that user, in every
organization. The browser session that made the change stays signed in, as before. Service-account tokens, other people's
tokens and integration secrets are not touched. An operator switch, `ONHOST_PASSWORD_CHANGE_REVOKES_API_ACCESS` (default
`true`), brings back the old "tokens kept" path and its `security-password-kept` mail without a deploy. The forgotten-password
reset already revoked all personal tokens. That is kept, and it now goes through the same helper and reports the count.
`panel.password` (sets the game panel account password) now needs the new HIGH customer permission
`service.panel_account.manage`. Only the `owner` role holds it: not org_admin, not developer, game_operator or cloud_operator,
no svc_* share role, not guest, not platform_owner. `ServiceService::requestAction` also refuses anyone who is not the
organization's `owner_user_id` acting in person (`owner_only_action`, 403, Czech message). The step-up is unchanged.
**Nothing reveals a panel password today.** The `panel_access` resource returns URL, username and e-mail only, so there is
no reveal path to close. The decision's "reveal/reset" is covered by the reset (set) path.

**Files.**

- `domains/Identity/ApiAccessRevocation.php` (new): `revokePersonalTokens(User, ?PersonalAccessToken $keep)`. It works only
  through the morph-scoped `User::tokens()` and marks rows revoked. It never deletes them.
- `app/Http/Controllers/Api/V1/MeController.php`: `changePassword` revokes when the switch is on. The audit detail and
  `security.password_changed` then carry `api_access=revoked` and `api_access_count`. With the switch off, the payload is
  byte for byte the old one.
- `app/Http/Controllers/Api/V1/AuthController.php`: `confirmPasswordReset` uses the helper. The count goes into the event
  and the audit detail.
- `config/onhost.php` and `.env.example`: `identity.password_change_revokes_api_access` / `ONHOST_PASSWORD_CHANGE_REVOKES_API_ACCESS`,
  in a delimited TASK-0021 entry.
- `domains/Notifications/NotificationRouter.php`: comment only. No routing change: `revoked` already sends `security-password`.
- `domains/Identity/Authorization/PermissionCatalog.php`: `service.panel_account.manage` (customer, HIGH) and
  `const OWNER_ONLY = ['organization.close', 'service.panel_account.manage']`, both in delimited TASK-0021 blocks.
- `domains/Identity/Authorization/RoleCatalog.php`: the org_admin line now reads `array_diff($allCustomer, self::orgAdminWithheld())`.
  **This is the one place for the org_admin exclusions.** The credit package adds `billing.wallet.spend` to
  `orgAdminWithheld()` and does not touch the role line. platform_owner drops `self::STAFF_NEVER = ['service.panel_account.manage']`.
- `domains/Services/Commands/ServiceActionCommand.php`: `permissionFor('panel.password') = 'service.panel_account.manage'`.
  Risk and step-up lists are unchanged.
- `domains/Services/Access/OwnerOnlyActions.php` (new), plus one call in `ServiceService::requestAction` just before the
  legal-hold check.
- `docs/architecture/events-catalog.md`: the `security.password_changed` row now says `revoked` after both a change and a reset.
- Tests: `tests/Feature/Http/PanelApiTest.php` (old "kept" test rewritten into a revoke test plus a switch-off test),
  `tests/Feature/Http/AuthApiTest.php` (reset pin), `tests/Feature/Identity/PermissionMatrixTest.php` (new column and a
  holder test), `tests/Feature/Provisioning/GameToolsFeatureTest.php` (owner-only test).

**Contracts.** No route, migration or command. The event payload gains `api_access_count` on the revoked path, and the key
avoids the `token` fragment. New config key and env var (above). New permission `service.panel_account.manage`. New error
slug `owner_only_action` (403). A non-owner who calls the endpoint gets `access_not_approved` from the bus first.
`features()` shows `panel_access` as `{enabled:false, reason:'permission'}` to non-owners, through the existing gate.
`ServiceFeatures.php` itself is not edited.

**Release note.** The RoleCatalog change reaches every organization through `AuthorizationSeeder` on deploy
(`infra/aapanel/deploy.sh` runs it). After that, org_admin, developer, game_operator, cloud_operator, svc_manage and
svc_console holders, and platform_owner, can no longer set a game panel password. Owners keep it, with the same step-up.
If the code goes live before the seeder runs, even owners are refused until it runs. This fails closed.
`onhost:doctor` "roles in the database match the catalog" must be green after the deploy. Nothing is revoked at deploy:
tokens are revoked only when a user changes their password afterwards.

  (org_admin saw `panel_access` enabled). AuthApiTest reset case (`Undefined array key "api_access_count"`). The switch-off
  case passed before the change, as it should: it is a guard.
- VERIFIED green: the same 4 files, 32 tests and 503 assertions. Related suites also pass: `tests/Feature/{Identity,Services,Organizations,Http,Notifications,Platform,Provisioning}`,
  `Compliance/AccountErasureTest`, `Support/AssistantProposalsTest` and `Catalog/PlanPromisesTest`, 580 tests in all.
- VERIFIED: `.\brain.ps1 gate -Quick -Tests …` returned PASS_WITH_PREEXISTING_FAILURES. The only failure is
  `Billing/RenewalGuardTest`, which is in the baseline list. Pint passes on the changed files, and Larastan on the changed
  PHP files reports 0 errors.
- NOT TESTED: full suite and full-repo Larastan; PostgreSQL (CI `pest-postgres`); the live Pterodactyl panel (no write flows
  against live panels).
- ASSUMED: after a reset, other SPA sessions are dropped by Sanctum's password-hash session check. The reset path does not

**Concerns.** Password change and reset are still controller writes outside the CommandBus, as before; this is not widened.
Support, platform_owner included, can no longer set a customer's game panel password. Such requests must go to the owner.
The `panel_access` resource (URL, username, e-mail) stays readable with `service.read`. `NotificationRouter`,
`events-catalog.md` and the org_admin line of `RoleCatalog` changed existing lines. Each change is one line, in place.
