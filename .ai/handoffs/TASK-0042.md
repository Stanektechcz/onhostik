# Handoff TASK-0042 — Grants follow one policy and access can be restored

- **From / To:** onhost-security → orchestrator
- **Task / Status:** TASK-0042 / SELF_VERIFIED
- **Outcome:** Permission program S1-01 and S1-02. Every grant entry point (invite, accept, role change, removal, project role,
  service share and revoke, ownership, restore, API token, partner attribution, staff) is decided by `GrantPolicy` against I1–I12,
  proven cell by cell in `GrantMatrixTest`. An access snapshot precedes every removal/role change and restores exactly; ownership
  moves only when the heir accepts; a lost owner is recovered by a CRITICAL, 7-day, cancellable `OwnerRecoveryCommand`, and
  `iam.mfa.reset` of a customer owner is refused. The grantor-loss cascade records by default and revokes only behind
  `ONHOST_GRANT_CASCADE_ENABLED`.
- **Review round 1 (all seven findings resolved, see the task file Findings R1-1…R1-7):** an `mfa_reset` recovery reaches every
  organization the owner owns or manages (one row each, `group_id`; each told, held, able to cancel all; stale if the reach grew);
  a staff party of a reached organization neither opens nor completes it; a staff or member-manager MFA reset is CRITICAL and every
  organization of the person is told (`organization.member.mfa_reset`); a restore covers what it takes away (I3); one pending
  recovery/offer per organization by partial unique index; a snapshot restored once under a race; cascade dedup by query.
- **S1-07 red team (task file Findings S7-1…S7-5):** a restore publishes the event of every loss it makes (`via: access_restore`) so
  SSH keys and game sub-users of a lost console go, and releases a guest it leaves with nothing; a removal revokes the person's API
  tokens bound to the organization for good (a demotion those the new role cannot carry) — a restore never brings them back; a
  restore must cover the remover's role (`access_snapshots.taken_by_role`, `snapshot_above_own`); a transfer-mode owner recovery
  takes the previous owner out (tokens, step-up). **S1-07 stays open**: it covered S1-01/S1-02 only; TASK-0043/0044 were never
  created, so S1-03..S1-06 and S1-08 have no code and the tokens-and-automation lens must run again once they exist.
