## Concerns (opposition to my own work)

1. **Root runs target PHP in a www-writable tree.** `vendor/` is ignored by the clean-tree check, so a compromised www
   user could plant code that root executes at `artisan down`. Open follow-up (root-owned code tree + `setpriv` + composer
   `--no-plugins`). The legacy staging tree is www-owned today.
2. **Deviations from the judged spec** (task file, *Deviations*): `--with-secret` instead of a secret file; curl `-K`;
   `EXPECTED_SHA` required everywhere; install.sh self-contained resolver; nginx realm variable instead of `satisfy any`
   (ASSUMED until S1); rc 6 does not re-down; activating units drained; CI e2e unprivileged.
3. **O7 has no data yet:** production has never run a night, so "size the window from production's nightly durations"
   can only use the S7 measurement until it has.
4. **The sandbox tests cost ≈ 100 s on Windows** (process spawning); on Linux CI much less. If the suite time matters,
   the 8 cases can be tagged and run only in `deploy-scripts`.
5. `ALLOW_DOCTOR_FAIL` accepts every failing GATED row of the run (the rows are logged), not one named row.
6. The lock for `Doctor.php` (TASK-0017) and `go-live-checklist.md` (TASK-0027) was refused; the text is below. Those
   locks look stale if PR #24 is merged — the orchestrator decides.
