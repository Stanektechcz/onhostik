## Concerns (opposition to my own work)

1. **Root still runs target PHP in a www-writable tree** (vendor/, app code; data root deserializes). Round 2 closed the
   framework-cache path and the symlink re-mode, not this. The follow-up (root-owned code tree + `setpriv` for artisan,
   composer `--no-plugins`) must name `bootstrap/cache`, `storage/framework/views` and cache/session data — a
   root-owned code tree alone does not cover them. Check-then-act races inside www-owned directories (cache publish,
   per-file chmod, view deletion) stay until those steps run as www.
2. **Deviations** (task file): `--with-secret`; curl `-K`; `EXPECTED_SHA` everywhere; install.sh self-contained
   resolver; nginx realm variable (ASSUMED until S1); rc 6 does not re-down; activating units drained; CI e2e
   unprivileged; round 2: `.env` "same file" (`-ef`) instead of "is a symlink"; new rc 7.

   (deploy.sh, install.sh): each script runs standalone. Round 3 added a guard test that the bodies are identical.
4. `UNIT_SETTLE` catches a unit that crashes on boot, not a worker that dies on its first job later; the doctor
   liveness rows six minutes after the release remain that check.
5. **O7 has no data yet:** production has never run a night; the window uses the S7 measurement until it has.
6. **The sandbox tests cost ≈ 5 min on Windows** (process spawning; 11 sandbox runs); on Linux CI much less. If suite
   time matters, tag them and run them only in `deploy-scripts`.
7. `ALLOW_DOCTOR_FAIL` accepts every failing GATED row of the run (logged), not one named row.
