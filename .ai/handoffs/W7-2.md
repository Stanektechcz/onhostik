## For security review (onhost-security): BREACH

HTML responses carry the CSRF token in the boot JSON (`window.ONHOST = { apiBase, csrf, user, surface, demo }`) and are
compressed (gzip today, brotli after the owner step). BREACH needs attacker-controlled input reflected in the same
compressed body as the secret.

- Looked at (ASSUMED, read only, not tested): `SurfaceRenderer` builds the boot object from server state (surface,
  user, demo flag, csrf); no request query value found in it. `SurfaceController` uses `getRequestUri()` only in a
  redirect `Location` header (`/prihlaseni?next=…`), not in the body.
- To verify: the login page body for `?next=` (is `next` echoed into HTML?), any surface or error page that echoes
  query/path into HTML next to the token, and whether the token is masked per response (Laravel's token is static per
  session — no masking).
- If a reflection is found: either drop the reflection, or exclude text/html from compression for authenticated
  surfaces, or mask the token per response. Without a reflection, compression of HTML stays acceptable.

Unverified: `nginx -t` with the change, staging headers after reload, brotli module availability, CI deploy-scripts lint.
